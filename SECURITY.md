# Security Policy

## Supported Versions

Boring Financial is currently in pre-release (`0.1.x`). Security fixes are applied to the latest code on the default branch.

## Reporting a Vulnerability

Please do not disclose exploitable details in public issues, pull requests, or discussions.

Preferred reporting path:

1. Use GitHub private vulnerability reporting from this repository's **Security** tab if it is available.
2. If private reporting is unavailable, contact the maintainer through the public contact methods listed on the maintainer's GitHub profile and request a private channel.
3. If neither option is available, open a public issue that only says you need a private security contact. Do not include reproduction steps, payloads, tokens, logs, or sensitive financial data.

Please include:

- Affected component or endpoint.
- Impact and prerequisites.
- Minimal reproduction details.
- Suggested remediation, if known.

The maintainer will acknowledge valid reports as soon as practical, coordinate a fix privately, and publish details after a patch or mitigation is available.
