\section{总体架构}

系统采用四层架构，自上而下分为展示层、网关层、服务层与数据/外部服务层，各层通过 HTTP 协议通信，职责边界清晰。

\begin{enumerate}
  \item \textbf{展示层}：Vue 3 + Element Plus + ECharts 构建的单页应用，运行于用户浏览器，负责全部用户交互与数据可视化。
  \item \textbf{网关层}：生产环境使用 Nginx 对外提供静态文件服务，并通过反向代理将 \texttt{/api} 请求转发至后端。开发环境使用 Vite Proxy 实现同源转发。
  \item \textbf{服务层}：FastAPI 构建的 RESTful API 服务，包含认证、导入、交易、分类、Dashboard 聚合、消费人格、家庭组织及 PDF 报表等业务模块。异步任务通过 Celery Worker 消费，外部模型调用通过 Retry Queue Worker 后台线程串行管理。
  \item \textbf{数据与外部服务层}：PostgreSQL（生产）/ SQLite（轻量部署）作为主数据库，Redis 作为 Celery 消息代理。外部服务包括 OpenAI-compatible API 与本地模型服务（vLLM），由 Retry Queue Worker 统一调度。
\end{enumerate}

\section{前端架构}

前端代码按职责划分为四层：视图层由 10 个页面组件构成，对应登录、Dashboard、导入、交易列表、校正工作台、分类管理、消费人格、家庭组织、报表中心和系统设置；状态层通过 Pinia Store 管理认证状态与 Token 持久化；通信层基于 Axios 封装 API 客户端，通过请求拦截器自动注入 Bearer Token；路由层使用 Vue Router 配置页面懒加载与导航守卫，未登录用户自动重定向至登录页。类型定义层为全部业务模型提供 TypeScript 接口约束。

前端视觉设计规范以深色导航（\texttt{\#06233D}）、品牌色（\texttt{\#00A884}）与浅灰页面背景（\texttt{\#F5F7FA}）构成统一视觉语言，详见第 4 章。

\section{后端架构}

后端按分层架构组织为四层。路由层（\texttt{api/}）通过 \texttt{router.py} 统一注册 10 个路由模块，覆盖认证、分类、导入、交易、分类校正、Dashboard、人格分析、家庭组织和报表生成。服务层（\texttt{services/}）承载全部业务逻辑：\texttt{imports.py} 管理导入批次与文件处理，\texttt{parsers.py} 实现多平台账单解析与规范化，\texttt{classifiers.py} 以复合分类链路编排规则、缓存与模型调用，\texttt{retry\_queue.py} 提供后台串行重试池，\texttt{analytics.py} 与 \texttt{personality.py} 负责聚合计算与人格分析，\texttt{organizations.py} 实现家庭组织 CRUD 与角色校验，\texttt{reports.py} 以 Builder 模式构建 PDF 报表。数据层（\texttt{models/entities.py}）定义 12 个 SQLAlchemy ORM 实体，\texttt{schemas/} 按业务域拆分的 Pydantic DTO 负责请求校验与响应序列化。基础设施层（\texttt{db/}、\texttt{core/}、\texttt{tasks/}）提供数据库会话管理、JWT 安全模块、配置加载与 Celery 异步任务定义。

\section{数据隔离策略}

系统通过以下机制保障多用户数据隔离与家庭组织聚合访问：

\begin{enumerate}
  \item \textbf{个人资源归属}：所有用户私有资源（交易、导入批次、上传文件、分类缓存、报表等）通过 \texttt{user\_id} 外键归属。系统分类的 \texttt{user\_id} 为 NULL，用户自定义分类的 \texttt{user\_id} 指向创建者。
  \item \textbf{查询过滤}：业务接口通过 Bearer Token 提取当前用户身份，查询时强制附加 \texttt{WHERE user\_id = current\_user.id} 条件。
  \item \textbf{家庭聚合模式}：家庭组织不改变交易归属。用户选择家庭视图时，前端传入可选 \texttt{organization\_id}。后端先通过 \texttt{OrganizationService} 校验成员身份，再收集组织内全部成员 \texttt{user\_id} 列表，传入 Dashboard、Personality 或 Reports 服务实现跨成员数据聚合。
  \item \textbf{默认模式}：\texttt{organization\_id} 为可选参数，不传入时各接口按个人账本口径返回数据，保持向后兼容。
\end{enumerate}

\section{部署架构}

系统支持两种部署模式以适应不同规模的运行环境：

\begin{description}
  \item[轻量本地部署] 使用 SQLite 作为数据库，\texttt{TASK\_ALWAYS\_EAGER = true} 使 Celery 任务在当前进程同步执行，Retry Queue Worker 在后台线程运行。前端通过 Vite 开发服务器或构建后的静态文件直接访问。
  \item[生产环境部署] Docker Compose 编排多容器服务栈：PostgreSQL 数据库、Redis 消息代理、Nginx 反向代理 + 静态文件服务、FastAPI/Uvicorn（监听 \texttt{127.0.0.1:8000}）、Celery Worker、Retry Queue Worker 后台线程。外部模型服务作为独立外部依赖。
\end{description}

通信链路为：用户浏览器 → Nginx（静态资源直接返回，API 请求反向代理至 FastAPI）→ FastAPI 与 PostgreSQL、Redis、Retry Queue Worker 通过内部网络通信。上传文件与 PDF 报表存储于 \texttt{storage/} 目录。
